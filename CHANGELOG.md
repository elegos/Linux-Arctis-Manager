## [Unreleased]

### Added (v3 daemon)

- v3: `representation` section in device YAML configs maps category names to status field lists; `GetStatus` now returns fields grouped by category instead of all under `"headset"`.
- v3: `display_type` field on `SyncEventField` (in `sync_events`) and `SyncReadMap` (in `sync_read`) lets YAML authors declare the GUI hint (`percentage`, `on_off`, `label`) for each status field; the hint is propagated through `EmitEvent.display_types` and written into the `"type"` key of the status JSON that `GetStatus` / `StatusChanged` emits. Annotated battery, mic volume, sidetone, brightness, gain, and Bluetooth toggle fields in `base_arctis_nova_pro_wireless.yaml`.
- v3: Device settings persistence — `SetSetting` saves the written value to `~/.config/arctis_manager/settings/<vid>_<pid>.yaml`; on daemon restart, persisted settings are re-applied to the device after successful init. `lam-integrity-check device-persistence` verifies the write-and-check path.
- v3: EQ model — `eq::preset` (BandMode: fixed_10/parametric_10/fixed_5, YAML round-trip), `eq::settings` (per-channel backend/band_mode/preset/app_overrides, YAML persistence), `eq::hardware` (HID payload encoders for NovaPro and ParametricNova families), `eq::ladspa` (mbeq_1197 LADSPA pipeline management: gain mapping for all 3 band modes, live pw-cli gain update without pipeline reload). `lam-integrity-check ladspa-eq` verifies load/update/unload lifecycle.
- v3: D-Bus EQ interface (`name.giacomofurlan.ArctisManager.Next.EQ`) — `GetEQCapabilities`, `GetEQSettings`, `SetEQSetting`, `ListPresets`, `GetPreset`, `SavePreset`, `DeletePreset`, `GetRunningStreams`, `GetSteamGames`; `EQChanged` signal. `eq_manager` handles LADSPA audio routing: loads/unloads the LADSPA sink and swaps the channel loopback target when EQ is toggled, supports live gain update without pipeline reload.
- v3: Virtual audio sinks (`Arctis_Media`, `Arctis_Chat`) now follow device lifecycle: created when a device session starts (on connect or daemon startup with device already present), torn down when the dongle is removed (previously the `handle.abort()` path skipped teardown) or when the daemon exits via SIGTERM or SIGINT. SIGTERM and SIGINT handlers added to `run_main_loop`.
- v3: PipeWire stream monitor for LADSPA backend app overrides (`stream_monitor`): subscribes to `pactl subscribe` for reactivity, snapshots clients on each `client` event, applies the first matching `AppOverride` preset per channel (stream name, executable basename, Steam `SteamAppId` env var), restores the channel default when the matching client disappears or settings change via `EQChanged`.
- v3: `GetEQCapabilities` now inspects the connected device's `apis` map: if `custom_eq` is present (Nova Pro family), returns `has_hw_eq: true, hw_band_mode: "fixed10"` instead of always `false`.
- v3: `SetEQSetting` now accepts `app_overrides` as a key (V3 `AppOverride` JSON array); the GUI's `dbus_wrapper` converts V2 flat override format to V3 internally-tagged `AppMatcher` format before sending. Backend selector row added to each EQ channel section (Auto / Software (LADSPA) / Hardware); hidden by default, shown when `GetEQCapabilities` reports `has_hw_eq: true`. `SetEQSetting` also sends `backend` on every apply.
- v3: Focus monitor for hardware-backend EQ app overrides (`focus_monitor` module). Structured as a module with isolated backend implementations sharing the `FocusEvent` interface: Hyprland IPC socket (`.socket2.sock`, `hyprctl` for PID), Sway IPC (binary framed protocol, PID native), X11/XWayland (`xprop -spy -root _NET_ACTIVE_WINDOW _NET_CLIENT_LIST`). Runtime backend detection via env vars (`HYPRLAND_INSTANCE_SIGNATURE` → `SWAYSOCK` → `DISPLAY`). GNOME Wayland is explicitly unsupported (no public API); reason surfaced via `GetEQCapabilities` as `hw_override_backend: "unsupported"` + `hw_override_unsupported_reason`; GUI shows a note label in each channel section. Focus stack per channel: EQ switches only when an app with a hardware override gains focus; non-override apps are transparent; app close restores the previous override or channel default. Stream monitor skips `Hardware`-backend channels (deferred to focus monitor).
- v3: At startup, non-command hidraw interfaces are skipped for PIDs that already have their command interface enumerated, eliminating spurious "headset not ready" loops on devices with multiple HID nodes (e.g. Nova Pro Wireless iface=3 and iface=4).
- v3: Virtual sinks are set up before `set-default-sink Arctis_Media` is called on connect, so the redirect always targets an already-created sink.
- v3: HID transport rewritten to use `AsyncFd<std::fs::File>` (epoll-backed) instead of `tokio::fs::File` (blocking thread pool). Cancelling a `read_interrupt` future — on timeout or task drop — is now immediate, so the daemon shuts down cleanly on SIGTERM without hanging until SIGKILL.
- v3: `SavePreset` now validates the preset before writing to disk — band count must match `band_mode`, and `frequency`/`filter_type` fields are required for `parametric_10` bands; invalid presets are rejected with a warning and return `false`.
- v3: Hardware EQ write path wired end-to-end. `HwEqContext` struct carries the device command channel and capability info (`native_band_mode`, `num_bands`, `custom_slot`, `has_preset_select`); built from `AppState` via `build_hw_eq_context`. `apply_channel_eq` now accepts `Option<&HwEqContext>`: when `backend` is Auto or Hardware and a matching context is present, sends `WriteApi("custom_eq", {gain1..gain10})` with gains clamped to ±10 dB, then `WriteApi("selected_eq_preset", {eq_preset: 18})` if the device supports preset selection. Band-mode mismatch with explicit `Hardware` returns false; with `Auto` falls through to LADSPA. `disable_channel_eq` resets the device to preset slot 0 when a context is provided. Stream monitor (`stream_monitor`) and D-Bus interface (`dbus.rs`) both build and pass `HwEqContext` at call time.
- v3: GeneralSettings — `GetSettings` now returns a populated `general` section (`redirect_audio_on_connect`, `redirect_audio_on_disconnect`, `redirect_audio_on_disconnect_device`) and their schemas in `settings_config`. `SetSetting` writes and persists general fields to `~/.config/arctis_manager/general_settings.yaml`. Default sink is redirected to `Arctis_Media` on headset connect (when enabled) and to the chosen device on wireless disconnect (when enabled). `lam-integrity-check general-settings` verifies the D-Bus contract.

When present, `field_to_schema` emits a `discrete_map` schema (type + default_value + values_mapping object) instead of a slider, regardless of range. `bt_call_default`, `wireless_mode`, and `eq_preset` in `base_arctis_nova_pro_wireless.yaml` now carry named mappings; `eq_preset` exposes all 19 preset slots (Flat, Bass Boost, Focus, Smiley, 14 game titles, Custom).
- v3: `SetSetting` now calls `build_write_values` before sending `WriteApi`: for multi-field structs (e.g. `stream_mix` with `stream_main`/`stream_aux`/`stream_mic`), sibling non-constant fields are read from `entry.status` and included in the write map, preventing codec "missing value" errors when only one field is changed.
- v3: `sweep_loopbacks_for_source` always unloads all existing loopbacks for `Arctis_Media.monitor` and `Arctis_Chat.monitor` at daemon startup and creates exactly one new loopback each, preventing accumulation when PipeWire does not preserve module args across client connections (the previous `pactl list modules short` args-based check was unreliable). The null-sink is still reused when present (checked via `pactl list sinks`).

- v3: Fixed `mic_router.rs` silently leaking a duplicate `Arctis_Manager_Mic` PipeWire module on every daemon restart that wasn't a clean shutdown (crash, `kill -9`, power loss) — found live-testing [E10-S5a] against PipeWire 1.6.8. `find_existing_module()` read `owner_module` from `pactl -f json list sources` as a JSON string (`.as_str()`), but this PipeWire version emits it as a JSON number; the `?` inside the scan loop then aborted the whole function the moment it reached the real entry, so the daemon always concluded no existing module was present and created a new one instead of reusing it. Fixed to accept `owner_module` as either a number or a string, and to `continue` past a non-matching or malformed entry instead of aborting the scan.

Fixed along the way, all found live-testing against the real interface: (1) `_register_vc_signals` called `iface.on_install_progress`/`on_install_complete` for signals `VcInterface` doesn't declare (no runtime deps to install in Rust) — `dbus_next` raises `AttributeError` for an `on_<signal>` accessor absent from the introspected interface, which aborted the *entire* signal registration before it reached `on_download_progress`/`on_download_complete`, silently breaking those too even though the daemon emits them correctly; removed. (2) Renamed `on_base_model_download_progress`/`_complete` to match the daemon's actual `BaseModelProgress`/`BaseModelComplete` signal names. (3) `GetVCCapabilities` now includes `rvc.models`/`models_folder`/`backends`/`ai_env_exists` — the model dropdown populates from this call, not a separate `GetRVCModels` call, on the widget's initial show. (4) `SetVCSettings` now gates actually running the LADSPA chain on the payload's `mode` field (`VcLadspaConfig` doesn't model it) — the GUI's "Enable" checkbox is independent of the mode selector, so selecting "AI Voice Changer" and enabling would otherwise silently run the unrelated LADSPA chain instead, since RVC mode has no backend to fall back to. (5) `vc_widget.py`'s calibration button stayed clickable with RVC unavailable — recording works standalone, but the wizard's auto-triggered render step would hang forever waiting for a `CalibrationStartRender` reply the daemon never sends (not in the interface, [E10-S6b]); now gated on `rvc.available`. (6) "Detect GPU" and "Install AI Dependencies" hung on "Detecting…"/disabled forever for the same reason (`DetectGPU`/`InstallAIDeps` aren't in the interface, [E10-S6a]) — both buttons are now always shown disabled with an explanatory tooltip instead.
- v3: Fixed `vc_ladspa_chain.rs` crashing the PipeWire filter-chain spawn when VC is enabled with every individual effect (pitch/chorus/delay/distortion/reverb) toggled off — a reachable first-time sequence (enable the master switch, then pick an effect) surfaced by the [E10-S5b] live GUI test. A filter-chain graph with zero nodes is a hard PipeWire error (`filter.graph has no nodes`, `pipewire` exits immediately, code 234) rather than an inert passthrough — unlike NC, these plugins have no bypass port to fall back to, so there was no valid graph to build. `apply_vc_ladspa` now treats zero active stages as inactive (tears down, returns no output source) instead of attempting the doomed spawn.
- Docs: added `voice-changer-rvc-pipeline.md` ([E10-S6a]) — technical architecture of the RVC inference pipeline (signal flow, windowing, model I/O shapes, ONNX conversion strategy) and its verification results: ContentVec, RMVPE, and the VITS-based synthesizer were exported to ONNX and checked numerically against PyTorch on real model files, all within tolerance (max diff 1.3e-7 / 1.2e-5 / 3.4e-3). Static shapes were used instead of dynamic axes (sidesteps a `LayerNorm`/`x.shape[-1:]` export failure in `synth_modules.py`, and this application's windowing is fixed-size regardless); the synthesizer's two internal `torch.randn`/`torch.rand` draws were externalised as explicit ONNX inputs, proven bit-exact equivalent to the original `.infer()` beforehand. The Rust engine itself is not started yet.
- v3: `vc_dsp.rs` ([E10-S6a], started) — first deterministic DSP functions from `pipeline.py` ported as pure Rust functions: `f0_to_coarse` (Hz → 0-255 quantised pitch index), `fill_f0_gaps` (interpolate short unvoiced flickers), `mix_rms` (envelope-shape mixing toward the input's dynamics), `soft_limit` (tanh-kneed output limiter). Each is verified against fixed test vectors computed by calling the real Python functions directly — same technique used throughout this migration (LADSPA control values, calibration downmix). Remaining DSP (VAD gate, VTLN frequency warp, SOLA crossfade alignment, RMVPE's salience decode) needs an FFT crate (`rustfft`) and lands in a follow-up.
- v3: `vc_base_models.rs` rewritten to resolve the RMVPE/ContentVec ONNX download dynamically instead of a hardcoded URL/version/checksum — fetches `elegos/Linux-Arctis-Manager-AI-Models`'s *latest* GitHub release via the API, reads `checksum.onnx.sha256` from it, and downloads `rmvpe.onnx`/`content_vec_best.onnx` by name against that manifest. A future re-export (e.g. for a newer ONNX opset) only needs a new GitHub release, not a daemon rebuild — the release is the single source of truth, nothing about its version or checksums is hardcoded here. The legacy Python (v2.5.x) daemon is unaffected: it stays pinned to the `v1` tag with hardcoded checksums, and never even requests anything from a newer release. Published `elegos/Linux-Arctis-Manager-AI-Models` release `v2` (not a pre-release — same model weights as `v1`, just also re-exported to ONNX) with both the original `.pt`/`.bin` files and the new `.onnx` files plus `checksum.onnx.sha256`; updated that repo's README accordingly. Added a manually-run (`#[ignore]`) live integration test that resolves the real published release end to end and checks both filenames' checksums are well-formed hex.
- v3: `vc_dsp.rs` gains the rest of the deterministic pipeline DSP: `vtln_warp` (frequency-domain formant warp via the new `realfft` dependency — numpy's `irfft` silently drops the imaginary part of the DC/Nyquist bins, which `realfft`'s C2R planner instead hard-asserts are already real, so those two bins are explicitly zeroed to match), `voicedness` (autocorrelation periodicity score, ported to a direct time-domain sum instead of the Python reference's FFT-based circular convolution — mathematically equivalent for lags `< n`, and simpler than adding a second FFT path for a one-shot-per-hop, small-array computation), `sola_offset` (the SOLA crossfade alignment search), `rmvpe_decode` (RMVPE's salience→F0/confidence decode, including the backward-only onset backfill), and `gate_envelope` (the input-envelope output gate's release curve, ported to an equivalent direct recursion instead of the Python reference's cumulative-max vectorisation trick). All five verified against fixed test vectors from the real Python reference functions. `vc/inference/` (the `ort` engine itself, `providers.rs`, `vc_retrieval.rs`, `vc_mel.rs`) is still not started — this closes out the DSP half of [E10-S6a].
- v3: `vc/inference/providers.rs` ([E10-S6a]) — execution-provider selection for the upcoming `ort` inference engine: builds the ordered `ExecutionProviderDispatch` list (CUDA → ROCm → OpenVINO → CPU) that `SessionBuilder::with_execution_providers` tries in order, falling through silently (and ultimately to ONNX Runtime's own CPU fallback) on registration failure — no explicit probing logic needed on this side, `ort` already does that. Adds the `ort` crate (`2.0.0-rc.13`) with the `load-dynamic` Cargo feature: `libonnxruntime.so` is resolved at runtime via `ort::init_from()`, not linked at build time, so enabling the `cuda`/`rocm`/`openvino` feature flags together adds no vendor-SDK build dependency — confirmed with a clean build on a machine with none of CUDA/ROCm/OpenVINO installed. Where the daemon actually obtains a working `libonnxruntime.so` at runtime is deferred to when the engine needs a real session to load (this module's own construction logic needs no FFI calls and is fully unit-tested without one).
- v3: `vc/inference/mel.rs` ([E10-S6a]) — native mel-spectrogram front end for RMVPE, which is *not* included in its ONNX export (`torch.stft` is exporter-finicky, see `voice-changer-rvc-pipeline.md`). Reproduces `rmvpe.py::_MelSpectrogram` — `torchaudio.functional.melscale_fbanks`'s HTK triangular filterbank (`mel_filterbank`, *computed* from the same formulas rather than embedded as a 65k-value literal, checked against `torchaudio`'s and `torch.stft`'s real GitHub source rather than reconstructed from memory) and `torch.stft`'s reflect-padded, periodic-Hann-windowed framing (`hann_window_periodic`, `stft_magnitude`, `mel_spectrogram`), via the new `realfft` dependency. Verified against Python reference vectors; one edge case worth noting for future porting work — a pure FFT leakage/noise-floor bin's exact value is float32-vs-float64 sensitive (real PyTorch tensors are float32; the initial Python reference generator used float64 and disagreed with this — correctly float32 — Rust output until regenerated in float32), so tests assert exact values only where the signal is meaningfully above the noise floor.

### Added

- Software EQ via PulseAudio LADSPA (`mbeq_1197` from `swh-plugins`): per-channel (media and chat) equaliser with simple (10-band) and advanced (15-band) modes, ±12 dB gain range per band.
- EQ presets saved as YAML in `~/.config/arctis_manager/eq_presets/`. EQ settings (enabled, mode, preset, per-app rules) saved in `~/.config/arctis_manager/eq_settings.yaml`.
- Per-application EQ overrides: route a specific running application, executable, or Steam game to a custom EQ preset on a chosen channel. The "Add override" dialog shows currently registered audio clients (including paused apps) for stream matching, a file browser for executable selection, and deduplicates Steam games that appear across multiple library folders.
- EQ curve widget: double-clicking a band dot resets its gain to 0 dB (editable presets only).
- LADSPA plugin availability check: if `mbeq_1197` is not installed, the EQ panel shows a warning banner with per-distro install instructions and a Retry button; all EQ controls are disabled until the plugin is detected.
- GUI daemon availability check on startup: if the background service is not running and `--no-enforce-systemd` is not set, the GUI silently enables and starts the systemd unit before opening; if `--no-enforce-systemd` is set and the daemon is offline, an error dialog is shown and the application exits cleanly.
- New dependency: `vdf>=3.4` (optional at runtime — Steam game matching is skipped gracefully if not installed).
- Daemon exposes a `GetVersion` D-Bus method returning the installed package version via `importlib.metadata`.
- UI footer (bottom-right) shows the running UI version. On a version mismatch the footer shows `UI: vX | Service: vY` while the issue is resolved.
- Automatic service upgrade: if the service version is older than the UI, or if the service does not expose `GetVersion` (pre-feature version), the GUI restarts the service once via systemd, re-writing the unit file so the current binary is used. After restart, the version is re-checked.
- If the UI is older than the service, a warning dialog prompts the user to restart the application instead.
- Noise Cancellation panel (side-menu entry): software microphone noise suppression via a LADSPA plugin chain.
- Five presets: **Off**, **Light** (HPF + RNNoise), **Standard** (+ noise gate), **Studio** (+ compressor), **Custom** (full manual control). Default: Standard.
- **Custom** mode exposes gate parameters (threshold, reduction, attack, release) and compressor parameters (threshold, ratio, makeup gain), each with a per-section reset-to-defaults button.
- Input device selector, defaulting to the detected Arctis microphone source.
- Runtime plugin detection: missing `ladspa-rnnoise-plugin` disables the whole panel with a banner and per-distro install instructions; missing `swh-plugins` disables only HPF/gate/compressor stages with a separate inline banner. Both banners include a Retry button.
- D-Bus NC interface stub (`GetNCCapabilities`, `GetNCSettings`, `SetNCSettings`) on `/NC` object path — daemon-side implementation is a separate task.
- Side navigation replaced with icon buttons (36 px system-theme icons, label underneath) using `QToolButton` with palette-aware highlight on selection and hover.
- Settings `discrete_map` fields now render as a `QComboBox` instead of a horizontal button group, preventing overflow for mappings with many options. Slider fields fire the D-Bus `SetSetting` call only on mouse release (`sliderReleased`) rather than on every intermediate `valueChanged`, preventing UI stutter from rapid daemon responses.
- GUI exits cleanly on window close: the D-Bus settings signal thread (`_register_settings_dbus_signal`) stores its shutdown future as `_stop_settings_signal_future` on `DbusWrapper` and resolves it in `stop()`, so the thread joins instead of blocking process exit.
- RVC voice changer: per-model advanced tuning (envelope mix, F0 smoothing, input drive, output limiter knee, VTLN formant warp) is now saved automatically per loaded model. An "Auto-tune" mode listens while you speak and lowers the input drive/envelope mix until output saturation (clipping) disappears, then saves the result.
- RVC guided voice calibration: a wizard prompts a short edge-case reading (word endings, nasals, sibilants, plosives, questions, trail-offs), renders it offline through three candidate tunings, and lets the user choose by ear (original recording included for reference), refine iteratively with narrower steps, re-record, or save the pick as the model's tuning.
- RVC FAISS feature retrieval (`.index` files): when a feature index sits next to the model (`<model>.index`), an "Index rate" per-model setting blends each voice feature with its nearest training-set neighbours — stabilising out-of-distribution input such as creaky word endings. Model zips and HuggingFace downloads now extract/fetch the index automatically, renaming it to match the model file; models with an index show a "(with index)" suffix in the model list. Requires `faiss-cpu` (added to the AI environment installer).
- RVC "Reset tuning" button next to the calibration wizard: reverts all of the current model's tuning parameters to the defaults after confirmation.
- Base AI models (RMVPE pitch estimator ~180 MB, ContentVec encoder ~360 MB) are now downloaded from the official [`Linux-Arctis-Manager-AI-Models`](https://github.com/elegos/Linux-Arctis-Manager-AI-Models) GitHub release instead of HuggingFace. Each file is verified against a SHA-256 checksum published in the release. A consent dialog informs the user of the download source and limited liability before any file is transferred. The RVC panel is disabled until both models are present. Download progress (filename + percentage) is shown in the application footer.

### Fixed

- Switching EQ presets, gains, or toggling EQ on/off no longer interrupts audio playback in apps such as Spotify, and no longer piles up dozens of unused PipeWire sinks over a session. Previously, every EQ change loaded a fresh LADSPA module and left the old one behind (idle, to avoid a PipeWire sink-removal event resetting playback streams). Changes are now pushed live to the existing LADSPA node instead, so the same sink and module are reused for the whole session — nothing to leak, nothing to reset.
- Internal EQ and noise-cancellation virtual devices are now clearly labelled (e.g. `Arctis Media EQ (internal)`) instead of showing truncated or garbled names in system sound settings.
- RVC voice changer: fixed a range of real-time synthesis artifacts — periodic clicking, dropped/garbled syllables at the start of phrases and after pauses, unintelligible isolated short words, and inconsistent output when repeating the same phrase. These were caused by issues specific to streaming (window-by-window) synthesis: hard cuts between overlapping synthesis windows, silence handling that fed the model artificial padding, and per-window randomness in the synthesizer.
- Noise cancellation: quiet consonants (e.g. nasals, word-final sounds) were sometimes being swallowed by the RNNoise/gate stages before reaching the voice changer, corrupting speech at the source; detection and gate release timing have been tuned to preserve them.
- Sidetone preview no longer stays silent when the underlying virtual audio routing had been rebuilt since the daemon started; the daemon also now self-heals that routing on restart.
- RVC voice changer: phrase endings no longer degrade into random vocals/mumbling. The pipeline gated speech with a fixed absolute threshold, so post-phrase breath and room noise were amplified and "voiced" by the model at full speech level. Gating is now level-adaptive (relative to the running speech level), quiet word-final vowels are preserved via a periodicity check so endings like "…Ginny" keep their final syllable, and phrase-final vocal fry is stabilised with wider F0 gap interpolation plus a speaker-relative pitch floor. The pitch anchor is outlier-robust: keyboard clicks and similar transients can no longer poison it (previously heard as the whole voice shifting up) nor open the gate from silence (heard as vocal blips when typing).
- Stopping the daemon no longer leaves an "audio return" (playback echoing back into the headset): the sidetone preview loopback survived teardown and was silently re-attached by the session manager to the headset's own monitor. The loopback is now pinned to its source, stale instances from crashed sessions are swept on preview start, and the preview restarts automatically when the voice-changer chain rebuilds (e.g. when switching models).

### Changed

- The Voice Changer panel is now labelled "Voice Changer (Preview)" — usable, but not yet considered production quality.
- The noise-cancellation chain now runs as a single native PipeWire filter-chain graph in a dedicated process, exposing exactly one recording device (`Arctis Manager NC Mic`) instead of one source per LADSPA stage plus a null sink and its monitor. Settings changes are pushed live to the running graph (disabled stages are neutralized/bypassed via their controls), so the microphone device never disappears from running apps when tweaking NC parameters. The previous per-plugin PulseAudio module chain is kept as an automatic fallback when PipeWire native tools are unavailable.
- Device detection now uses the USB iProduct string (e.g. `Arctis Nova Pro Wireless`) as the primary identifier, scoped to the SteelSeries vendor ID. Product IDs remain as a tiebreaker when multiple configurations share the same product name (e.g. Nova 7 Wireless discrete vs. percentage battery variants), and as the sole matching method for configurations that do not declare a `product_string`. This allows firmware updates that change the product ID to still be recognised automatically; unknown PIDs that match by name log a warning suggesting udev rules may need updating.
- EQ apply path: replaced 5–10 sequential `SetEqSetting` D-Bus calls with a single atomic `SetEqChannelSettings(channel, json)` call per channel. The daemon deserializes `ChannelEqSettings` directly and calls `apply_channel_eq`/`disable_channel_eq` exactly once. The GUI now tracks which channel changed and only sends that channel's data; the explicit "Apply" button still sends both channels.
